# H-ECS R3 successor C2M — matched constituent family, frozen DEV/QUAL protocol with H2 hierarchy adjudication (prospective; science unstarted at freeze)

`RESEARCH_ONLY` · `NO_RUNTIME_AUTHORITY` · `NO_RUNTIME_READINESS_CLAIM` · `NO_INTEGRATION`

## Authority and question

C2 (`research/hecs_r3/successor_c2/`) is `WORLD_MODEL_VALID`: DEV 8/8 and C2-Q2 QUAL 12/12. In C2, only the HD/L2 ROLLOUT arm was trained by the C2 law. The other three bindings kept the R3 paired law. A hierarchy comparison over C2's models would therefore confound hierarchy with unequal training.

Following the operator's choice of option 1, C2M is a **new matched constituent family**. The same C2-derived learning law trains the ROLLOUT model of **every** constituent that the H2 comparison consumes. The family receives its own DESIGN → fresh DEV → fresh QUAL discipline before any hierarchy comparison counts.

This protocol asks two questions, in order.
1. **Validity.** Does C2M pass the unchanged frozen validity hierarchy (TASK → S1 → M) at every seed, binding and bound horizon of a fresh, never-executed 8-world DEV registry? If and only if it does, does it pass again on a fresh, never-executed 12-world QUAL registry?
2. **Hierarchy.** Only if QUAL is `WORLD_MODEL_VALID`: what is the R2 H2 outcome (H2A/H2B/H2C) on QUAL, computed from planning over the matched models?

DEV H2 values are reported and non-binding. No hierarchy claim is made from DEV, from DESIGN or from an invalid QUAL.

## Learning versus query (binding constraint)

The C2M law is **offline TRAIN/LEARN mechanics**. One scientific seed rebuilds every constituent from G1: 96,000 native G1 steps per binding, then 4096 C2 updates per binding. Each seed is an independent qualification replicate. It is never the work of one Elpis turn.

The H2 planning evaluation is **QUERY**. The trained W of each constituent is materialized once into a K1 ECS (`create(DIM, width, MAX_ROWS, W)`). Planning then performs native forward computation only: no learn call and no optimizer update.

Two limitations are recorded:
- The C2 law's true-target terminal anchor uses true future latents during training. C2M is therefore a learning law from observed trajectories, not an instant query-time method for building a model from novel context.
- A passing hierarchy adjudication is not a runtime-readiness claim. Persistent-runtime qualification (`../successor_c2/ARCHITECTURE_CONSTRAINTS.md`) is a separate, later milestone.

## Family C2M (frozen)

**Engine.** `r3_bn_c2m_dev_engine.rs` is the frozen C2 engine source, byte-for-byte outside the documented C2M diff (generated by counted replacements). Its support modules are `r3_training_core.rs`, `r3_bd_emitter.rs` and `r3_c2_terminal.rs` (all unchanged from C2), plus the new `r3_c2m_planning.rs`.

**Unchanged from C2:**
- native K1 G1, 96,000 steps;
- the bindings (L1/N72 h16, L1/N36 h4, TS/L2 h4, HD/L2 h4), their windows and their measurement;
- the G1 arm and all task rows (T1, T3, V2–V5);
- RATE = 0.0005·36/width, CLIP = 10, LAMBDA = 0.37;
- the C2 law itself: C2_UPDATES = 4096, six picks `windows[(7s+j) mod n]` (j = 0..5) per update, exact reverse-mode gradient, and the R3 update/clip rule;
- the terminal weight at h = 4: 1.0.

**Changed:** the C2 law, and C2's teacher-only TEACHER arm, now apply at **every** binding at that binding's consumed horizon h (16 at L1/N72, 4 elsewhere). The terminal weight is defined per consumed horizon: **w_T(h) = (4/h)^1.5**.
- At h = 4 (L1/N36, TS/L2, HD/L2) this is exactly the qualified C2 weight, 1.0.
- At h = 16 (L1/N72) it is 0.125.

The engine holds these as exact literals and refuses any other horizon.

`L = mean_windows[ e_1 + (λ/(h−1))·Σ_{t=2..h} e_t + w_T(h) · e_h ]`, with `e_t = 0.5·‖ẑ_t − z_t‖²/(LATENT·var)`.

- ẑ is free-running from the true z_0 through G_W with the true actions. z_t are true training latents.
- At h = 4 this is exactly the qualified C2 objective.
- A numerical escape in any C2 update is a committed scientific failure of that binding's ROLLOUT arm: event stage `C2_OPTIMIZER`, which fails TASK_LOCAL under the frozen law. It is never retried.

**Planning (H2, QUERY-only).** `r3_c2m_planning.rs` holds `kind_tag`, `episode_setup`, `EpisodeStats` and `run_episode`, copied verbatim from `hecs_r2 experiment.rs`. `plan_conditions` reproduces `run_seed`'s H2 accounting over the three H2 conditions:

| Condition | Models | Budgets (planner K) |
| --- | --- | --- |
| FLAT_N72 | L1/N72 | [8, 32, 128] |
| TEMPORAL_SHARED_L2 | L1/N36 + TS/L2 | [16, 64, 256] |
| HIERARCHICAL_DISTINCT_L2 | L1/N36 + HD/L2 | [16, 64, 256] |

Planning runs in the SEPARATED world with PLAN_EPISODES = 24, PLAN_STEPS = 64 and REPLAN_EVERY = 4. The models are the matched C2M ROLLOUT W of the seed, materialized into K1. Each seed writes `planning.tsv`, 9 rows, next to the five-file set.

Planning runs only if all four ROLLOUT arms were measured. Otherwise the file holds only its header. That seed has a failure event and therefore already fails TASK_LOCAL.

A native K1 error during planning is a mechanics failure (supervisor FAULT), never a scientific verdict.

Port identity: on G1 weights (DESIGN world `15483355346944449004`), `plan_conditions` reproduces `hecs_r2::experiment::run_seed`'s SEPARATED planning for all 9 condition/budget rows. Success and forward rows per replan, the H2 inputs, match bitwise (`DESIGN_RECORD.json`, `planning_port_identity`).

## Selection basis (DESIGN only; `DESIGN_RECORD.json`)

DESIGN worlds: the 32 C2 DESIGN-train worlds, the 8 burned successor DEV worlds and the 48 C2 DESIGN-holdout worlds. No C2M DEV/QUAL world and no executed or spent C2 world was used.

1. **The unchanged C2 law** (w_T = 1.0 at every binding), screened over 40 worlds:
   - L1/N36 h4: 40/40 pass, min bound M 0.9944.
   - TS/L2 h4: 40/40 pass, min 0.9731.
   - L1/N72 h16: **38/40, min M16 0.8843**. It is therefore not valid at h16. (The R3 law there: 40/40, min 0.9574.)
2. **Diagnosis.** At h16 the w_T = 1.0 terminal term drives the pre-clip gradient norm to about 12–15 (clip 10 active on 64–80% of updates), and h8/h16 capture degrades. On the 6 worst worlds, the base objective alone for 4096 updates is robust.
3. **Pre-declared rule** (written before the grid ran). Grid p ∈ {0.5, 1, 1.5, 2} in w_T(h) = (4/h)^p, which leaves every h4 binding at the qualified C2 weight. Choose the p with the highest minimum bound M over the 40 worlds among those with 40/40 pass; tie → smaller p.
   - w_T(16) = 0.5: 0.9212; 0.25: 0.9809; **0.125: 0.9857**; 0.0625: 0.9855.
   - All four pass 40/40. Selected: p = 1.5.
4. **Held-out confirmation** (48 worlds, never used for selection):
   - L1/N72 h16, w_T = 0.125: 48/48, min 0.9920.
   - L1/N36 h4: 48/48, min 0.9923.
   - TS/L2 h4: 48/48, min bound M 0.9604 (h2), min S1 0.9649.
   - HD/L2 h4: the identical, qualified C2 law, 48/48 with min 0.9764 in the C2 DESIGN record.
5. **Full-engine DESIGN runs and supervisor rehearsal** (`DESIGN_RECORD.json`). The C2M engine's rows reproduce the DESIGN harness rows bitwise at L1/N72, L1/N36 and TS/L2. They reproduce the frozen C2 engine bitwise for G1/TEACHER at every binding, for ROLLOUT at HD/L2, and for the task and V5 rows. A rehearsal of the generated supervisor on 2+2 DESIGN worlds, run in a separate scratch root, exercised: release, six-file commit, cohort close with the H2 line on DEV and QUAL, and the QUAL lock.

Planning and H2 values on DESIGN worlds were computed only to verify mechanics after the law was fixed. They were never a selection input.

For transparency: on the 6 full-engine DESIGN worlds, HIERARCHICAL_DISTINCT_L2 planning success was far below FLAT_N72 and TEMPORAL_SHARED_L2 at every budget. R2's own planning on G1 weights showed the same pattern (port-check world). This disclosure is not a prediction and not a gate. The QUAL outcome is whatever the frozen H2 law computes.

**Tightest DESIGN margin, pre-registered.** TS/L2 one-step capture (S1 ≥ 0.95) has a lower tail. Its minimum over 88 DESIGN worlds is 0.9649. On the 40 screen worlds it was 0.9731 under C2M and 0.9700 under the R3 law, so it is not worsened by C2M. It is a world-driven risk, and no world is screened for it.

**Interpretive caution, pre-registered.** C2M equalizes the learning law (objective structure, update budget, windows and rate rule) across constituents. It does not equalize training compute: an h16 update has four times the recursive transitions of an h4 update. Like the R2 law, H2 equalizes planning compute through the budget points.

## Evidentiary law

**Validity: unchanged R3-BP arithmetic.** The C2M observer is the frozen C2 observer, whose per-seed recomputation and cohort decision law are byte-for-byte R3-BP. It adds two things:
- a `planning.tsv` census: 9 rows; each condition/budget pair exactly once; K equal to the spec budget; success in [0,1] and a multiple of 1/24. The file may be empty only for a seed with a failure event.
- the H2 computation.

On the legacy successor cohort and on the C2 DEV cohort, its validity outputs equal those of R3-BP and the frozen C2 observer.

Gates, in order (bindings L1/N72 h16, L1/N36 h4, TS/L2 h4, HD/L2 h4):
1. **TASK:** T1, T3, V3, V5 per seed, and no event (any event fails TASK_LOCAL); V2 and V4 as cohort means.
2. **S1:** ROLLOUT one-step capture ≥ 0.95 at every binding.
3. **M:** ROLLOUT capture ≥ 0.90 and escape ≤ 0.01 at every binding and every h ≤ consumed horizon.

**Every seed means every seed.** One failure at any world, binding or horizon fails the phase. Dispositions follow the R3-BP priority order:
- `DEV_WORLD_MODEL_VALID_CONDITIONAL_QUAL_ELIGIBLE`;
- `WORLD_MODEL_VALID`;
- `TASK_INVALID_ON_*`, `ONE_STEP_MODEL_INVALID_ON_*`, `WORLD_MODEL_INVALID_ON_*`.

**Pre-registered, candidate-independent TASK risk.** Task validity depends only on the world. Across C2's DESIGN, about 1 world in 40 exceeded the frozen MATCHED T3 L/G limit of 1.20. A TASK-invalid DEV or QUAL world fails the phase under the frozen law. It is recorded as TASK-invalid, which is not a world-model verdict, and reported for an operator decision. No world is screened, replaced or re-drawn.

**H2 hierarchy law: R2 spec, unchanged** (`hecs_r2 spec.rs` thresholds, `experiment::evaluate` arithmetic).
- succ(condition, budget) is the mean SEPARATED planning success over all phase seeds.
- H2A = succ(HD) − succ(FLAT) ≥ 0.15, H2B = succ(HD) − succ(TS) ≥ 0.10 and H2C = succ(TS) − succ(FLAT) ≥ 0.10. Each holds if its difference meets the threshold at ≥ 2 of the 3 budget indices.
- Outcome: `DISTINCT_ADVANTAGE` (H2A and H2B) > `TEMPORAL_ADVANTAGE` (H2C) > `UNATTRIBUTED_ADVANTAGE` (H2A) > `NO_ADVANTAGE_OVER_WIDTH`.
- `HIERARCHY_ADJUDICATED` only on QUAL with disposition `WORLD_MODEL_VALID`. On DEV the line reads `DEV_NON_BINDING`. On an invalid QUAL it reads `HIERARCHY_NOT_ADJUDICATED`, which is not a hierarchy result.
- The observer prints `R3_C2M_H2 … INTEGRATION_AUTHORIZED=NO` in every case. Under operator direction, the next milestone after an adjudication is persistent-runtime qualification, not integration.

Every H2 outcome, including `NO_ADVANTAGE_OVER_WIDTH`, is a valid scientific result of the matched comparison. No outcome is retried, re-planned or re-drawn.

## Execution law

The C2M supervisor is derived from the frozen C2 supervisor template, including the C2-Q2 R1 `prefix(phase)` correction. It adds:
- `planning.tsv` as a sixth committed file;
- the planning source digest in the release;
- `HIERARCHY=` and `H2_OUTCOME=` in the disposition record.

Everything else is unchanged:
- a write-once release per phase, binding every binary, source, library tree, protocol, DESIGN record, registry and the K1 digest;
- the QUAL release is refused unless the committed DEV disposition reads `DEV_WORLD_MODEL_VALID_CONDITIONAL_QUAL_ELIGIBLE`;
- strict index order with the START/COMMIT chain re-admitted before every seed;
- `FAULT.txt` with `REPLAY_PERMITTED=NO`;
- one cohort calculation after the last seed, then a write-once disposition.

Prohibitions:
- No retry, replay, seed replacement, rescue, retuning, threshold change or gate reordering.
- No parameter change after a DEV seed starts.
- No QUAL rerun after a QUAL seed starts.
- A failed DEV closes C2M; any successor needs a new DEV registry.
- A failed QUAL closes C2M as failed QUAL; any future lineage needs a new QUAL registry.

An infrastructure interruption (container restart, operator-side kill) is recorded as an operator incident, never as a fabricated supervisor FAULT and never as a scientific verdict, and is escalated to the operator.
